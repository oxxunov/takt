# Архитектура

## Дерево модулей

Зависимости строго однонаправленные, обратных стрелок нет:

```
:app  ──>  :engine  ──>  :core
```

| Модуль    | Тип             | Что внутри                                    | Знает про Android |
|-----------|-----------------|-----------------------------------------------|-------------------|
| `:core`   | Kotlin JVM      | модель, генератор раскладки, судейство, формат кэша | нет           |
| `:engine` | Android library | нативный анализатор, декодер, плеер, звук, настройки | да           |
| `:app`    | Android app     | экраны, отрисовка, игровой цикл               | да                |

`:core` не имеет ни одного импорта из `android.*` или `androidx.*`.
Именно поэтому логику генератора и судейства можно проверять юнит-тестами
за секунды, без эмулятора: `gradle :core:test`.

## Поток данных

```
файл (URI)
   │
   ├─ PcmDecoder ──────────> моно float PCM        :engine (MediaCodec)
   │                              │
   │                              v
   ├─ NativeAnalyzer ───────> Analysis             :engine -> C++ через JNI
   │                              │
   ├─ AnalysisCache ─────────┤ бинарный .rga       :engine
   │                              │
   ├─ BeatmapGenerator ─────> Beatmap              :core   (мгновенно)
   │                              │
   ├─ GameEngine ────────────> оценки, счёт        :core   (чистая логика)
   │                              │
   ├─ GameSession ───────────> игровой цикл        :app    (Choreographer)
   │                              │
   └─ GameView ──────────────> кадры               :app    (только рисует)
```

Кэшируется **результат анализа**, а не готовая раскладка. Анализ занимает
секунды, генерация раскладки — микросекунды. Поэтому сложность и ползунок
плотности пересобирают уровень мгновенно, без повторного разбора файла.

## Границы, которые держатся намеренно

**Отрисовка ничего не решает.** `GameView` получает `RenderSource` (снимок
для чтения) и `InputSink` (куда отдать касание). Он не знает про движок,
про звук и про то, закончилась ли партия. Кадры можно ронять и терять —
на судейство это не влияет.

**Игровая логика идёт по Choreographer, а не по циклу отрисовки.** Раньше
`engine.update()` вызывался внутри `draw()`, и пропущенные ноты зависели от
того, успел ли отрисоваться кадр.

**Звук подключён к движку через слушателя.** `GameEngine` сообщает
`onJudged`/`onFinished`, а `GameSession` решает, что с этим делать. Движок
не знает про существование звука, поэтому его можно прогнать в тесте.

**Источник времени — интерфейс.** `GameClock` реализован `MusicPlayer`'ом;
в видеорежиме на его место встанет ExoPlayer, и игровой слой не изменится.

**Один граф зависимостей.** `AppGraph` — единственное место, где создаются
`Prefs` и `AnalysisCache`. Раньше они создавались заново в каждой Activity.

**Тяжёлая работа отменяема.** Анализ идёт в `viewModelScope`, а не в
`thread {}` внутри Activity: задача снимается при выходе и не держит контекст.

**JNI привязан таблицей, а не именами символов.** `RegisterNatives` в
`JNI_OnLoad`: при переименовании пакета библиотека не загрузится вообще,
вместо тихого `UnsatisfiedLinkError` через полминуты игры.

**Звуковой движок — экземпляр, а не синглтон.** Калибровка и игра раньше
дрались за общий поток AAudio через общий `start`/`stop`.

## Что проверено, а что нет

Проверено запуском:

- Анализатор (C++) собран g++ и прогнан на синтетических треках:
  BPM 127.95 при истине 128.0, recall онсетов 100%, средняя ошибка
  тайминга 4.9 мс, фаза сетки в пределах 8 мс. 4-минутный трек — 796 мс.
- Утверждения тестов генератора перепроверены на эквивалентном
  Python-прототипе: плотность, минимальные интервалы, равномерность
  дорожек, реакция на ползунок, отбрасывание внесеточных онсетов.
- Согласованность проекта: пути пакетов, ссылки `R.*`, число аргументов
  формат-строк, соответствие сигнатур JNI объявлениям Kotlin,
  однонаправленность импортов между модулями.

Не проверено (нет Android SDK/NDK в среде сборки этого кода):

- Компиляция Kotlin и сборка Gradle.
- Юнит-тесты `:core` написаны, но не запускались.
- Всё, что требует устройства: AAudio, MediaCodec, AudioTrack, отрисовка.

## Тесты

```
gradle :core:test
```

CI гоняет их отдельной работой перед сборкой APK: `:core` не тянет Android
SDK, поэтому логика падает за секунды, а не после долгой сборки.
